Como ter um stub sem conflitar com o `if(f.fbq)return` O problema ocorre porque o SDK oficial do Meta usa exatamente este padrão: ```js if (f.fbq) return; ``` Se você cria: ```js window.fbq = function() { ... } ``` antes do SDK ser carregado, o SDK interpreta que já existe uma instância válida e interrompe a inicialização. A solução mais segura é: ### Não criar `window.fbq` antes do SDK Use uma fila separada: ```js window._fbqQueue = []; function trackFb() { window._fbqQueue.push([...arguments]); } ``` Exemplo: ```js trackFb('init', PIXEL_ID); trackFb('track', 'PageView'); ``` Enquanto o SDK não existir, tudo entra na fila. Quando o SDK terminar de carregar: ```js script.onload = () => { fbq('init', PIXEL_ID); for (const args of window._fbqQueue) { fbq.apply(null, args); } window._fbqQueue = []; }; ``` Dessa forma: * `window.fbq` não existe antes do SDK * o `if(f.fbq)return` não dispara * o SDK cria o `fbq` oficial * a fila é drenada após o carregamento --- ## 2. Como garantir que a fila seja drenada corretamente O erro mais comum é este: ```js fbq('track', 'InitiateCheckout'); ``` executar antes de: ```js fbq('init', PIXEL_ID); ``` Quando a fila é drenada, o Pixel ainda não está inicializado. A ordem correta é: ```js script.onload = () => { fbq('init', PIXEL_ID); while(window._fbqQueue.length){ fbq.apply(null, window._fbqQueue.shift()); } }; ``` Ou ainda melhor: ```js window._fbqReady = false; script.onload = () => { fbq('init', PIXEL_ID); window._fbqReady = true; while(window._fbqQueue.length){ fbq.apply(null, window._fbqQueue.shift()); } }; ``` E o helper: ```js function trackFb(...args){ if(window._fbqReady && typeof fbq === 'function'){ fbq(...args); return; } window._fbqQueue.push(args); } ``` Assim: * Antes do SDK → fila. * Depois do SDK → envio imediato. * Nenhum evento é perdido. --- ## O que eu verificaria agora Se o evento continua zerado no Meta, mesmo após corrigir a fila, os suspeitos mais fortes passam a ser: ### 1.
